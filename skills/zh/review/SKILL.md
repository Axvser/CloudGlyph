# 审核

## 职责

对产出物进行逐一审核与改正

## 检查清单

### 覆盖率对账矩阵（硬性关卡）

依据功能清单的「覆盖率状态」列构建矩阵。矩阵必须写入审核输出——它是交付物，不是内心演练。

| 功能 | 证据来源 | 快速入门 | API | SE分析 | 状态 |
|---|---|---|---|---|---|
| 用户注册 | Demo | ✅ | ✅ | ✅ | 通过 |
| 数据导出 | Test | ✅ | ✅ | ❌ 缺少数据流子页 | 不通过 |
| 主题定制 | *推断所得* | ✅ | ⚠️ 部分：仅 setTheme | ✅ | 通过（遗留） |

规则：

- **证据来源为 Demo / Test 的功能，三个维度（快速入门 / API / SE 分析）必须全部 ✅。任一 ❌ ⇒ 整个审核不通过。** 立即修正后重新审核。
- **仅「推断所得」功能可带有 ⚠️ 遗留项**，且每个遗留项必须写明一行原因（如「公开表面未被证据完全覆盖」）。
- 对账完成后把最终状态写回功能清单（`通过` / `不通过` / `遗留`）。
- 若清单仍为 `TODO` 或与已完成页面矛盾的陈旧状态 → 不通过；状态机未被遵守。

---

### 用法完整性审计

- [ ] 每个功能模块的快速入门是否覆盖了其最上层 API（特性/Fluent/扩展方法）
- [ ] API 参考是否覆盖了「功能清单」中找到的所有公开类型和成员
- [ ] 代码示例是否同时展示了**声明式**和**命令式**两种使用风格

---

### Demo 阅读验证（前置检查）

在开始逐页审计前，先确认编写阶段是否履行了强制完整阅读义务：

- [ ] 对每个有 Demo 的模块，确认文档中覆盖了**该模块 Demo 目录下所有源文件**所展示的使用模式，而非仅片段
- [ ] 对每个仅有测试的模块，确认文档覆盖了测试文件中的关键用法和边界情况
- [ ] 如有 Demo 但文档有明显缺失的模式 → **标记不通过**，要求 Agent 重新完整阅读 Demo 后补写

---

### 代码真实性验证（关键 — 逐页全面审计）

对 Wiki 的**每一页**，提取所有包含 API 引用的代码块。对每个引用：

- [ ] **发现优先级合规** — 确认代码示例优先来自 Demo 项目（优先级 1）或测试（优先级 2）。如果仅使用了优先级 3（从源码推断），确认已明确标注为*推断所得*。
- [ ] **类/方法名** — 搜索代码库确认每个类型和成员存在且**签名一致**
- [ ] **命名空间/模块路径** — 验证与实际项目结构及源码声明一致，不得臆造路径
- [ ] **方法参数和返回类型** — 交叉对比源码声明；文档必须符合实际
- [ ] **异常声明** — 如果文档列出了异常，确认它在方法签名或文档注释中存在
- [ ] **属性/字段名** — 文档中引用的每个属性或字段必须在声明的类型上存在
- [ ] **已移除/已过时 API** — 标记任何文档中对已弃用（deprecated）或已移除成员的引用
- [ ] **无编造代码** — 每个代码块必须可追溯到真实的源文件

---

### 可复现性抽检

- [ ] 每个快速入门都有强制「前置条件」块（SDK/运行时/包管理器版本、目标框架、所需服务）
- [ ] 每个编号步骤都有可观测的「预期结果」
- [ ] 完整代码块中**无 `...` 省略号**；每个标识符都定义于示例、前序步骤，或可追溯到真实文件
- [ ] 页面以「运行声明」页尾结束：`✅ 实际构建并运行`（记录输出）或 `⚠️ 未实际运行`（仅静态核验，已标注）
- [ ] 任何 `✅` 声明，其记录输出与该步骤声明的预期结果一致

---

### 图表语法验证

- [ ] **Mermaid** — 方向/类型有效、参与者已声明、括号平衡、箭头正确
- [ ] **KaTeX** — 所有 `$...$` 和 `$$...$$` 行内/块级成对平衡，无错配分隔符
- [ ] **PlantUML** — `@startuml` / `@enduml` 成对、参与者使用前已声明、`activate`/`deactivate` 成对、`alt`/`else`/`end` 结构正确

---

### 结构一致性

- [ ] 数字前缀符合约定（如 `01_`、`02_`）
- [ ] 每个页面目录（根目录和子页面）都存在 `index.md`
- [ ] 代码块缩进使用实际空格（Space）而非制表符（Tab），宽度与【编码风格约定】一致
- [ ] 无本地 Markdown 链接（`[text](local/path/)`）
- [ ] **清理未操作条目** — 凡不是本次工作流产出的文档页面或目录，必须删除。如果删除相关文件后父目录变空且不影响当前产出结构，该空目录也必须一并移除。

---

### 跨语言对等

- [ ] 如果启用多语言，**每个**页面在**所有**选定语言中都存在
- [ ] 跨语言版本无缺失或过时页面

---

### 导航索引验证

- [ ] **执行导航脚本** — 运行 `python gen_tree.py`（如项目配置不同按实际脚本名）重建 `tree.json`
- [ ] **验证脚本输出** — 确认生成的 `tree.json` 包含**所有**新页面且嵌套正确
- [ ] **构建项目** — 运行项目的构建命令确认编译通过

## 预提交流程

1. 按检查清单逐项走查，发现问题的**立即修正**再继续下一项
2. 代码真实性发现问题 → 使用源码搜索确认签名后修正文档
3. 图表语法发现问题 → 修正后重新验证
4. 对账「覆盖率对账矩阵」：若任一 Demo/Test 功能存在 ❌，或矩阵未产出，质量门不通过
5. 对快速入门页面执行「可复现性抽检」
6. 执行 `python gen_tree.py`，确认无遗漏页面
7. 运行项目的构建命令，确认编译通过
8. 所有项 ✅ 后，标记质量门通过
